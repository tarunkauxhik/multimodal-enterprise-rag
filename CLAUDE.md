# Multimodal Enterprise RAG

GitHub is the source of truth. The VPS is deployment/runtime only (runs Qdrant and the app).

## Pipeline (benchmarked — do not replace without explaining why first)

PDF
→ PyMuPDF4LLM extraction
→ selective Grok 4.7 multimodal understanding (only pages that need it)
→ structure-aware chunking
→ Gemini Embedding 2
→ Qdrant (dense) + separate rank-bm25 index
→ application-level RRF
→ Jina reranking
→ Grok 4.7 grounded answer + citations

| Decision | Value |
|---|---|
| LLM (understanding + answers) | xAI `grok-4.7` (`LLM_PROVIDER`/`LLM_MODEL`), Chat Completions over httpx, key `XAI_API_KEY`, base URL `XAI_BASE_URL` (default `https://api.x.ai/v1`). Replaced the benchmarked MiniMax-M3 (gateway unavailable); Grok is not benchmarked here |
| Embeddings | `gemini-embedding-2`, 768 dims, `RETRIEVAL_DOCUMENT` / `RETRIEVAL_QUERY` |
| Vector store | Qdrant, cosine, 768 dims |
| Sparse | `rank-bm25`, separate local/in-memory index (V1) |
| Fusion | RRF in app code, k=60; dense top 20 + BM25 top 20 → top 10 |
| Rerank | `jina-reranker-v3`, RRF top 10 → top 5 |
| Generation | Grok 4.7 over the top 5 chunks, `reasoning_effort` low (`GENERATION_REASONING_EFFORT`; Grok cannot disable reasoning, returns it separately in `reasoning_content`, which is never read) |
| Citations | `[document.pdf, Page X]` (validated against supplied chunks); bare `[Page X]` accepted only when exactly one supplied document has that page |

All of these live as constants in `rag/config.py`.

## Rules

- Stack: Python 3.12, Qdrant, `api.py` (a thin FastAPI adapter that holds no RAG logic; it calls `rag.session` and `rag.store`), and the `web/` frontend (Next.js, TypeScript, Tailwind, shadcn/ui, Lucide). No LangChain, LangGraph, Redis, Celery, Postgres, WebSockets/SSE, Kubernetes, another backend, or extra framework layers.
- `web/` is presentation only: it talks to FastAPI through its `/api/*` proxy (`web/app/api/[...path]/route.ts`: five allowlisted endpoints, streamed request bodies, replies reduced to the fields the UI uses, error details only for the fixed 404/409/413/415/429 messages) and `web/lib/api.ts` (the only place that calls it). No retrieval, prompts or citation validation in the frontend, and it never shows chunk ids, scores, write ids or internal document ids. Document text, file names and sources render as plain text; answers only through `AnswerMarkdown` (no HTML, images or links except citation markers). No `dangerouslySetInnerHTML`. Source passages render through `components/sources/passage.tsx` via `lib/passage.ts`: conservative cleanup of extraction artifacts (bold markers, escapes, link targets dropped; `<mark>`/`<u>` highlight and underline spans unwrapped to their text), `<sup>`/`<sub>` as real super/subscripts, headings, pipe tables as real tables, figure captions as titles; every cell and line stays React text, and any other tag-like text stays literal. Every emoji renders as an Apple emoji image via `components/emoji.tsx` (`Emoji`, `EmojiText`, and `rehypeAppleEmoji` for answers); `web/public/emoji/` is generated by `scripts/copy-emoji.mjs` and never committed.
- Add a dependency only in the step that needs it; prefer stdlib or already-installed packages.
- API keys come only from environment variables (`rag.config.load_settings`). Never hardcode, print, or log them.
- Never commit PDFs, databases, caches, model files, BM25 index files, or `.env`. Runtime data lives under `data/` (gitignored).
- One module per pipeline stage in `rag/`; no interfaces with a single implementation.
- Non-trivial logic gets one small test in `tests/`.
- Git: commits and pushes are authored and committed solely by `tarunkauxhik`. Never add `Co-Authored-By`, "Generated with", session links, or any other AI attribution to commits, PRs, or code. Never change `git config user.*`.

## Commands

```
uv sync                                   # create .venv from pyproject/uv.lock
uv run pytest                             # backend tests (offline; in-memory Qdrant, fake embedder)
uv run python -m rag.ingest file.pdf ...  # extract -> chunk -> embed -> Qdrant (idempotent)
uv run python -m rag.retrieve "question"  # hybrid retrieval, prints top 5 with citations
uv run uvicorn api:app --host 127.0.0.1 --port 8000 --workers 1  # HTTP API (single worker only)
cd web && npm run dev -- --hostname 127.0.0.1   # web app on :3000 (start the API first; RAG_API_URL overrides its address)
cd web && npm test && npm run lint && npm run typecheck && npm run build   # frontend checks (Vitest, ESLint, tsc, standalone build)
RAG_LIVE_TESTS=1 uv run pytest tests/test_live_retrieval.py -v -s  # real Gemini/Jina/Qdrant, multilingual
```

Local Qdrant: Docker container `rag-qdrant` on 127.0.0.1:6333, volume `rag_qdrant_storage`.

## Deployment (VPS)

- Production shape: Nginx (HTTPS, access control) → Next.js standalone server (127.0.0.1:3000) → FastAPI (127.0.0.1:8000) → Qdrant (127.0.0.1:6333). Files in `deploy/`: `rag-api.service`, `rag-web.service` (after the API), `nginx.conf`. Nginx proxies only to Next.js; never add a location that reaches FastAPI or Qdrant directly.
- Nothing has authentication and the workspace is shared, so Nginx basic auth for the whole site (`deploy/nginx.conf`, `/etc/nginx/rag.htpasswd`) is a deployment requirement; never expose the site without it. Do not add app-level auth in V1. Keep FastAPI, Next.js and Qdrant bound to 127.0.0.1 (`-p 127.0.0.1:6333:6333`).
- Run exactly one Uvicorn worker (`--workers 1`): upload jobs live in memory. Nginx must cap request bodies (`client_max_body_size 200M;`), since Starlette receives an upload in full before the API's own size check; the Next.js proxy streams bodies and adds no limit of its own.
- Single API process assumed. API clients are shared across request and ingestion threads on the assumption they are thread-safe (normal usage for httpx, google-genai, qdrant-client); load-test during deployment.
- The VM also runs unrelated services (e.g. the Hermes container): do not touch them.

## Data flow notes

- One shared workspace: the HTTP API (`api.py`) uses `API_COLLECTION` (default `documents`, the collection the CLI's `rag.ingest`/`rag.retrieve` use), so CLI-ingested documents appear in the web app; it lists documents from Qdrant payloads (`rag.store.list_documents`, no chunk text) and runs ingestion on a single background thread (`ThreadPoolExecutor(max_workers=1)`), keeping each job's live `IngestReport` in memory.
- Web app (`web/`): polls `GET /api/documents` every 2 s only while a document is queued or processing or an upload is waiting (`hooks/use-documents.ts`), and sends uploads one at a time within the API's queue capacity, retrying after a 429 once the list refreshes. Upload progress comes from XMLHttpRequest. Conversation history is display-only, kept in the tab's sessionStorage; each question is one `POST /api/chat` and earlier turns are never sent. Citations arrive validated and normalised as `[document, Page N]` in the answer; `lib/citations.ts` only numbers them and groups sources by document page. API errors map to fixed user messages (`lib/api.ts` `errorMessage`); server detail text is never shown. The proxy marks an unreachable API with `x-rag-unreachable`.
- Session-collection helpers in `rag.session` (`start_session`, `touch_session`, `cleanup_inactive_sessions`, `delete_session`: private collections that expire after 24 h idle) served the former Streamlit app and are not used by the API.
- Uploaded documents with a name already in the workspace get a " (2)" suffix (`rag.session.unique_source_name`) so `[document, Page N]` citations stay unambiguous.
- Multimodal understanding (`rag.understand`): after fast extraction, only pages flagged `scanned` (little text + large image), `garbled` (U+FFFD in text), `legacy_font` (at least half the page's Latin letters in a known pre-Unicode Hindi font such as Arjun or Kruti Dev, read from the PDF's text spans into `Page.legacy_font_share`), `legacy_text` (fallback when no listed font matches: Latin text with few vowels and punctuation inside words), `figure` (large figure whose caption is not an event-photo caption such as "Glimpses…", "Hon'ble…", "…held at…") or `table` (mostly empty cells) are rendered at 150 DPI and sent to Grok 4.7 (`UNDERSTAND_REASONING_EFFORT` low). Its output is stored as extracted document content (never an answer): scanned pages become `figure` blocks (tables stay `table`), figures get their visual content, garbled and legacy pages are re-transcribed as `text`. Any failure keeps the fast extraction. Successful results are cached in `data/cache/understanding.sqlite` (the key includes `LLM_PROVIDER/LLM_MODEL`, so another model's results are never reused; bump `PROMPT_VERSION` to invalidate).
- Embedding cache: `data/cache/embeddings.sqlite`, keyed by sha256(model, dim, task, text). Cached texts are never re-embedded.
- IDs: `document_id` = sha256(PDF bytes)[:16]; `chunk_id` = `{document_id}-p{page}-{n}`; Qdrant point id = uuid5(chunk_id).
- Completeness: `replace_document` stamps every point with `chunk_total` and a per-write `write_id` (keyword-indexed). A document is complete only when all its points share one `write_id` and their count equals `chunk_total` (`rag.store.complete_write_ids`, the single definition). `list_documents` reports anything else as incomplete (the API's `incomplete`), and `Retriever.refresh_bm25` derives the set of complete writes from Qdrant on every refresh: BM25 indexes only their chunks and dense search filters `write_id` to that set, so a partial or interrupted write is never retrieved, across restarts too. Points stored before these fields existed are therefore not retrieved until re-ingested (idempotent and cached). The fields never reach prompts or API responses.
- Re-ingesting a document upserts its points, then deletes that document's stale points.
- Chat routing (`rag.route.classify`, used by `rag.session.respond`, the API's chat entry point): deterministic, no model call, and only the user's message and document names influence it (never document text). Conversation intents (greeting, thanks, ack, farewell, help, followup) touch nothing; list_documents/page_count/vague use the payloads the `Retriever` already loads; term expands short abbreviations from document text (`expand_term`, quoted, never invented); overview (one named document, else a clarifying question) and page send chosen chunks to `generate_answer`; question is the full pipeline. The API returns `kind` and `suggestions`; `abstained` is true for `abstain` and `out_of_scope`. The API is single-turn: the web app shows history, but each message stands alone (bounded conversation context is a V2 item, not built). `page_number` is the physical PDF page (1-based, from PyMuPDF4LLM metadata); replies speak of "indexed pages" because the PDF's total page count is not stored. Overview evidence is `rag.session.overview_evidence` (title chunk, contents section, informative early chunks; skips cover lines and abbreviation/glossary sections; first 30 pages). Abbreviations are expanded per document; different meanings in different documents produce a "which one?" clarification. The web proxy validates every chat/document value at runtime (types, known enums, lengths) rather than trusting the upstream shape.
- Generation (`rag.generate.generate_answer(query, [hit.payload for hit in hits], llm_client(...))`): retrieved text is sent only as delimited untrusted `<source>` blocks; `<think>` is stripped; `[document, Page N]` citations not matching a supplied (document, page) are removed; no context, `INSUFFICIENT_CONTEXT`, or no valid citation → abstention; `OUT_OF_SCOPE` (question not about the documents) → the scope refusal. Neither refusal ever answers from general knowledge. Grok 4.7 always reasons (it cannot be disabled) and returns the trace in `message.reasoning_content`, which `llm_client` never reads, so only `message.content` is used; `<think>` stripping stays as a provider-neutral safeguard. Both roles use `reasoning_effort` low. `finish_reason == "length"` raises instead of returning a truncated answer. HTTP 408/429/5xx, transport errors and malformed replies are retried; other HTTP errors fail at once, with the key redacted. `Answer.raw_output` keeps the unprocessed reply for evaluation.
- The rank-bm25 index is built in memory from Qdrant chunk payloads (`rag.bm25.build_bm25(rag.store.iter_payloads(client))`), so it never drifts from the dense index. Rebuild after ingestion.
